## The Question Nobody Can Answer

Your team uses GitHub Copilot ($19/dev/month), Cursor ($20/dev/month), maybe Claude Code. On 100 developers, that's **$24K-120K per year**.

Your CFO asks: "Is this worth it?"

You don't know. I didn't know either.

## What Exists Today

I looked for tools:

| Tool | Problem |
|------|---------|
| **Exceeds AI** ($4.6M raised) | $49/manager/month, closed-source |
| **GitHub Copilot Metrics** | Copilot-only, acceptance rates only |
| **Jellyfish, LinearB, GetDX** | Engineering metrics, but can't attribute code to AI |
| **Surveys** | Self-reported, unreliable |

Nothing open-source. Nothing that measures both **speed AND quality**.

## So I Built DevPulse AI

[DevPulse AI](https://github.com/TimurRakhmatullin86/devpulse-ai) connects to your GitHub repos via a GitHub App and answers the question with data.

### How It Detects AI-Assisted PRs

Four levels, each with a confidence rating:

1. **HIGH** — `Co-Authored-By` headers (Copilot, Claude, Cursor automatically add these)
2. **MEDIUM** — Commit message patterns ("Generated by", "[ai]", "🤖")
3. **MEDIUM** — PR body markers ("generated with Claude/Copilot")
4. **LOW** — AI config files present (`.cursor/`, `CLAUDE.md`)
5. **EXPERIMENTAL** — Heuristic: 500+ lines changed in <30 minutes with ≤2 commits

**I'll be honest:** this is marker-based detection, not AST analysis. If a developer removes the `Co-Authored-By` header, we can't see it. I'd rather under-count than over-count.

### The Metrics

| Metric | What It Measures |
|--------|------------------|
| **AI Usage Rate** | % of PRs detected as AI-assisted |
| **Speed Multiplier** | Cycle time ratio: non-AI / AI |
| **Rework Rate** | % of PRs that needed fix commits within 14 days |
| **Bug Rate** | Bugs filed within 14 days of merge |
| **Code Churn** | Lines changed then reverted within 14 days |
| **Review Load** | Average review comments per PR |
| **Net Productivity Score** | Speed gain minus quality cost |

### The Dashboard

Six views:
- **Executive Summary** — one ROI number, the "elevator pitch" for your CFO
- **Speed vs Quality** — side-by-side comparison with bar charts
- **Developer Scatter** — plot each developer by AI usage vs rework rate
- **Repository Breakdown** — which repos benefit most from AI
- **Weekly Trends** — 12-week line charts showing adoption curve
- **ROI Calculator** — input license costs + average salary, get dollar impact

## What the Data Actually Shows

From our demo dataset (modeled on real-world patterns):

| Metric | AI PRs | Non-AI PRs |
|--------|--------|------------|
| Avg cycle time | 4-5 hours | 8-10 hours |
| Rework rate | 12-15% | 7-9% |
| Review comments | 3-8 | 1-5 |
| Net productivity | +12% to +17% | baseline |

**AI coding tools make you faster. They also make you slightly sloppier.** The net effect is positive, but modest — not the "10x" that vendors claim.

The most interesting finding: the developer who uses 0% AI has the **lowest rework rate** on the team. Make of that what you will.

## Try It

### Demo Mode (no GitHub account needed)

```bash
git clone https://github.com/TimurRakhmatullin86/devpulse-ai
cd devpulse-ai
docker compose up -d db
npm install
cp .env.example .env
npx prisma db push
npm run db:seed
npm run dev
# Open http://localhost:3000 — sign in as demo@devpulse.dev
```

### Production Mode

1. Create a GitHub OAuth App
2. Create a GitHub App (for webhooks)
3. Set environment variables
4. Deploy to Vercel or Docker

Full instructions in the [README](https://github.com/TimurRakhmatullin86/devpulse-ai).

## Tech Stack

- **Frontend:** Next.js 14 (App Router), Tailwind CSS, Recharts
- **Backend:** Next.js API routes, Prisma ORM
- **Database:** PostgreSQL
- **Auth:** NextAuth.js (GitHub OAuth + demo credentials)
- **GitHub API:** Octokit (REST + webhooks)

## Why Open Source?

The market for AI developer analytics is consolidating. Exceeds AI raised $4.6M. The big players (Jellyfish, LinearB) are adding AI features to their platforms.

But engineering teams shouldn't need to pay $49/manager/month to answer a basic question about their own data. If you can self-host Grafana for observability, you should be able to self-host your AI tool analytics too.
